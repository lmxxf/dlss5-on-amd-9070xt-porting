0.40 update
1. Same kernels and default configuration as the regular package: all 71 blocks + fast numerics (against NVIDIA 44.26 -> 47.55 dB, about 0.12/0.19 ms slower per frame); for the 0.39 output write DLSS5_SKIP_BLOCKS=42,43,46 and DLSS5_FAST_NUMERIC=0 in custom-config.txt.
2. Multi pass DLSS5_MULTI_PASS=1/2/3 (default 1, stronger style, about N times the cost). The RE9 runtime has no hotkey; edit the config and restart the game.
3. The runtime reads the three config files (see "Config files" below) and now also takes DLSS5_STYLE, DLSS5_FRAME_STATS, DLSS5_FAST_NUMERIC, DLSS5_MULTI_PASS, DLSS5_MULTI_PASS_SKIP_BLOCKS and DLSS5_NETWORK_FREE_RES from them (the DLSS5_STYLE line of the 0.39 template now works). Behaviour change: a key written twice in one file now takes the last line (before, the first).
4. Direct input (one 35 MB copy less); GetTimings for integrators. Host dxgi.dll unchanged.

Config files (three layers from 0.40; a later layer overrides the same key of an earlier one)
1. DLSS5-AMD/default-config.txt: the package defaults (repository template). Overwritten by every upgrade; do not edit it.
2. DLSS5-AMD/custom-config.txt: your own settings. Not shipped: copy custom-config.template.txt to custom-config.txt the first time and write only the lines you change (e.g. DLSS5_MULTI_PASS=2). Install and upgrade never touch it.
3. DLSS5-AMD/native-game-flags.txt: the old single file. An existing one keeps working and wins over custom-config.txt; packages no longer ship it, so unpacking an upgrade over an old install leaves it alone.
A DLSS5_* system environment variable wins over all three files. Same key twice in one file: the last line wins; an empty value (KEY=) means the built-in default.

Lossy options (all optional; put them in custom-config.txt)
- On by default: DLSS5_FAST_NUMERIC=1 (fast numerics; worst frame about 51.8 dB against the bit-exact output, essentially unchanged against NVIDIA; 0 = bit-exact, 0.07-0.13 ms slower per frame).
- DLSS5_SKIP_BLOCKS=42,43,46: skip three blocks, 0.20/0.32 ms faster (900/1080), about -3.3 dB against NVIDIA with an overall colour shift. Together with DLSS5_FAST_NUMERIC=0 this is the 0.39 output.
- DLSS5_NETWORK_1080_ROWS=1088: 1080 tier about 0.45 ms faster, about 54-56 dB against 1152 rows.
- DLSS5_NETWORK_HEIGHT=900: inputs that would use the 1080 tier run at 900, about 2.7 ms faster; quality cost not measured.
- DLSS5_MULTI_PASS_SKIP_BLOCKS: skip blocks in multi-pass passes 2..N only. Saves little; longer lists change the style. Not recommended.

0.32 update (configurable)

For Resident Evil Requiem's special command submission; not the generic OptiScaler edition. The host derives from TheAutomatic's release/1.9.0 and uses our HIP runtime. Credit to TheAutomatic for the pre-SR host design and contribution.

Pipeline: low-resolution game rendering → HIP DLSS5 → FSR → display. Unlike0.27's post-FSR/1080p-output route, this supports tested2560x1440 borderless output. Neural INPUT must still be≤1920x1080; network resolution auto-selects720/900/1080. Same-frame game exposure is applied before inference and undone afterwards to prevent the washed-out input caused by omitted exposure. Detail/Colour strength default to1. Includes six common lossless kernel improvements and preparation of lazy HIP kernels/weights before staged submission.

Exit the game and extract all files next to re9.exe after backing up existing mods. Remove older dlss5-amd.addon64, re9-present.addon64 and observer add-ons from both root and _storage_. If _storage_ already contains dxgi.dll/LmxxfNrRuntime.dll/OptiScaler.ini, update those copies too. The host and runtime are a matched pair. REFramework's dinput8.dll is included; resolve conflicts with other dinput8 mods first.

Select DLSS in game. Start with2K/Balanced and frame generation off; test frame generation separately after confirming stable rendering. No personal game config or saves are included.

F6 toggles NR. Insert opens OptiScaler/REFramework (their default keys can overlap). Use the neural menu to adjust Detail strength/Colour strength, keeping both in0..1. Reducing Colour strength also suppresses coloured texture/material changes, not just saturation.

Settings are in OptiScaler.ini [DlssNr]: NrBackend=lmxxf, Enabled=true, RunBeforeSR=true, LmxxfDiagnostic=off. Information overlays use OptiScaler controls. Old addon F7 and DLSS5_SHOW_FPS/NOTICE do not control this runtime. DLSS5_HIP_*, DLSS5_SKIP_BLOCKS, DLSS5_FIT_LARGE, DLSS5_NETWORK_HEIGHT and the keys listed in the 0.40 update are read from the three config files in DLSS5-AMD (other keys have no effect); no standard-addon F8/F9 hotkeys. Default: all 71 blocks + fast numerics; adaptive reuse is off.

RX9070XT numerical/exposure tests, menu rendering and repeated startup have passed. Full gameplay, scene changes and frame generation still need further feedback. Previous0.27 Xbox Onimusha validation does NOT validate this new host. Other RE games/gfx1200 hardware/HDR display output remain unverified.
