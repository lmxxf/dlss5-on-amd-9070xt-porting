# Configuration reference

[简体中文](CONFIGURATION.zh-CN.md) · [English README](../README.md)

## All annotated defaults

The complete bilingual option comments, including compatibility and historical experiment keys, live in the templates below. Releases stage the selected template as `DLSS5-AMD/default-config.txt`. This page explains controls, precedence and host differences without duplicating the full inventory. Historical DX12/test keys are not automatically active in HIP or supported by RE9; RE9 accepts only the whitelist below.

| Host | Annotated default |
|---|---|
| Regular OptiScaler add-on | [hip-game-flags.txt](hip-game-flags.txt) |
| Magpie add-on | [hip-magpie-flags.txt](hip-magpie-flags.txt) |
| RE9-specific runtime | [hip-re9-flags.txt](hip-re9-flags.txt) |

Write overrides in `custom-config.txt`, starting from the [custom template](custom-config.txt). For example, `DLSS5_STRENGTH=0.7,0.3` controls detail-lighting and colour separately. Check higher-priority native/environment layers first. Current source defaults prediction to 1 only at 3 passes, with explicit 0 for real three-pass computation; 1x/2x are unchanged and skin protection defaults to 0. These defaults ship in 0.41; older ZIPs have not been retroactively updated.

## Three configuration layers (source since 2026-10-03)

Three optional files under `DLSS5-AMD\` are read in order. The shared implementation is `src/native_config_layers.h`.

| Order | File | Owner | Installation/upgrade |
|---|---|---|---|
| 1 | `default-config.txt` | Package, from these templates | May be overwritten on upgrade |
| 2 | `custom-config.txt` | User | Never overwrite; packages ship only `custom-config.template.txt` from `scripts/custom-config.txt`; deployment creates the user file only if absent |
| 3 | `native-game-flags.txt` | Legacy single-file configuration | Existing files keep their meaning and remain effective; new packages do not ship one |

Rules:

- A later file overrides the same key from an earlier file. Missing keys inherit earlier values; a missing file is skipped.
- Existing process `DLSS5_*` environment variables have highest priority, captured when configuration is first read. Add-on and RE9 readers skip these keys when applying file values to the environment; hot reload and direct file reads use the same merged result.
- After trimming trailing CR/LF/spaces, a line must start with `DLSS5_`, contain `=`, and have at least eight characters. The first `=` separates key and value. Comments beginning with `#`, blank lines and descriptive text are ignored. An initial UTF-8 BOM is skipped. The old 255-byte line-length limit no longer applies.
- Within a file, the **last occurrence wins**. This was already true for the add-on; the RE9 runtime previously used the first occurrence.
- An empty value, such as `DLSS5_SKIP_BLOCKS=`, overrides earlier layers with an empty result. `_putenv` then removes that environment variable, restoring the built-in default.
- RE9 accepts only `DLSS5_HIP_*`, `SKIP_BLOCKS`, `FIT_LARGE`, `NETWORK_HEIGHT`, `NETWORK_1080_ROWS`, `STYLE`, `DIRECT_IO`, `NETWORK_FREE_RES`, `FAST_NUMERIC`, `MULTI_PASS`, `MULTI_PASS_SKIP_BLOCKS`, `MULTI_PASS_SKIN_PROTECT`, `MULTI_PASS_PREDICT`, `FRAME_STATS` and `STRENGTH` (all with the `DLSS5_` prefix). It finds the first folder containing any layer, looking in `DLSS5-AMD\` beside the DLL or up to four levels above the asset directory.
- Add-on hot reload watches timestamps of all three files; editing, creating or deleting any file rereads the merged result. The multi-pass hotkey (F9 by default) writes `custom-config.txt`. If the legacy native file also sets `DLSS5_MULTI_PASS`, that line is rewritten too; an existing environment variable still wins and stderr reports that the change cannot take effect.
- The add-on recognises a configuration directory beside its DLL when any of the three layer files exists, rather than requiring the old native file.

Tests: `tools/test_config_layers.cpp` contains 28 checks, runnable natively on Linux or as a MinGW-built Windows executable.

RE9 reads the whitelisted network settings from `hip-re9-flags.txt`; `re9-presr.ini` overlays the OptiScaler host and does not replace the network file. Current package assembly uses `Development/tools/package-040.ps1` and `stage-config-layers.ps1` to copy default and custom templates, never the player's actual custom/native files. `-ConfigDirectory` must point to templates from the same commit. Version 0.41 packages passed separate packaging and release validation. Template comments use two lines, Chinese and English, each at most 191 bytes.

## Configuration controls

| Key | Default | Meaning and applicability |
|---|---|---|
| `DLSS5_PRE_UPSCALE` | `auto` (regular template since 2026-10-03) / `0` (Magpie / RE9 templates) | Add-on only; the RE9 runtime never reads this key (it has one route). `1` = pre-upscale route: the network runs before the FSR upscale, which requires the title's upscaler dispatch to be the tail of its command list (the Stellar Blade contract). `0` = post-upscale route. `auto` (since 2026-10-03): the first processed frame probes that contract — if draw/dispatch work follows the upscaler dispatch in the same command list (Forza Horizon 6, Wo Long 2), the add-on permanently falls back to the post-upscale route for the session and logs the reason in `logs\native-pre-upscale.txt`, instead of dying as a fatal passthrough ("installed but does nothing"); otherwise it stays on the pre-upscale route. The decision is sticky; an unrecognised value behaves as `0`, the previous behaviour. `2` = FFX-only smoke replay (diagnostic, unchanged). During the probe frames the `DLSS5_PRE_UPSCALE_ASYNC` rules still apply (Cyberpunk 2077's quirk table stays in force); after a fallback the pre-upscale route is off, so ASYNC no longer matters. Read once; restart needed. |
| `DLSS5_PRE_UPSCALE_ASYNC` | `auto` (regular template) / `0` (Magpie) | Pre-upscale submission. `auto`: asynchronous except for titles in the add-on's quirk table (Cyberpunk 2077: transient aliased colour buffer needs synchronous submission). `1`/`0` force it. |
| `DLSS5_STRENGTH` | `auto` | Two numbers: transfer/detail-lighting and colour blend. Add-on/Magpie accepts each 0..3 (1 full, >1 diagnostic extrapolation); RE9 accepts each 0..1. No single-value broadcast. Add-on auto: 1,1 except Cyberpunk2077 1,0. RE9 auto/empty/unset keeps the explicit host/menu strength or the runtime default 1,1; a valid numeric file/system-environment value overrides the host/menu. Invalid/nonfinite/trailing junk RE9 values fall back to host/default and report once. File layers remain default→custom→native→existing process environment; native `auto` still overrides custom, so remove/comment the old native line to customise in custom. Add-on edits apply within one second; RE9 config needs restart, while its host menu remains live when no numeric override is set. `0` suppresses output enhancement, not network computation or an exact F6 bypass; strength changes neither Style nor MultiPass. |
| `DLSS5_HIP_PDL` | `1` (0.30 templates) | Chain launches of the C64/C128/C256 blocks go out with `hipExtAnyOrderLaunch` and the kernels wait on / publish per-tile flags (programmatic-dependent-launch emulation); the next launch fills the previous one's tail. Bit-exact; 900p about -1.6%, 1080p about -0.6%. `0` restores plain in-order launches. |
| `DLSS5_HIP_VIT_STREAM` | `3` (0.35 templates) | ViT attention writes its AV output as bytes straight into the n64 projection and the contract step uses the half interface (`vit-stream` module); works with adaptive ViT reuse. Bit-exact; 1080p about -1.3%, 900p about even. `0` keeps the previous f32 path; a missing module falls back to it and logs `vit_stream:nomodule`. |
| `DLSS5_FRAME_STATS` | `0` | Seconds per window of a frame-time log appended to `DLSS5-AMD\logs\frame-stats.txt`: frames, fps, frame interval avg/p50/p99/max (0.25 ms buckets up to 100 ms), 1% low, and how many frames the network ran / was bypassed (F6) / initialising / error / unsupported / idle. Interval = time between upscaler dispatches, not GPU time. Regular add-on reads it from the config files; RE9 runtime from the environment the config files set (whitelisted since 2026-10-03; before that environment only; RE9 counts run/error per EnqueueHip only). `0` = off, no cost. |
| `DLSS5_DIRECT_IO` | `1` (add-on; RE9 runtime since 2026-10-02: bit 1 only, from the environment or the flags file) | Zero-copy I/O around the HIP network, pure data movement (network input/output bytes and the final image are bit-identical). Bit 1: the RGB input pass writes the network input straight into the HIP-shared buffer (skips a 35 MB copy and an unused tile-order copy). Bit 2: on the pre-upscale route, FSR reads the decoder output texture directly instead of a copy of it (RGBA16F colour only; other formats copy as before). History/temporal sessions and `DLSS5_OVERLAP` keep the old path. `3` = both, `0` = previous behaviour. |
| `DLSS5_HIP_WAVE_OWNED` | `0` (source builds after 0.30) | Opt-in single-wave window kernels for the updated Magpie/regular OptiScaler add-on. Requires its matching `c32-wave1.hsaco` and `c64-wave2.hsaco`; compatible production byte-stream settings activate it, incompatible layouts retain the old path. `0` restores prod8 dispatch without loading extra modules. Full runtime regression passed; game FPS validation and release packaging pending. The separate RE9 C API runtime is not enabled by this flag. |
| `DLSS5_HIP_SWIN_RUN` | `1` (0.37 templates, all three: regular / Magpie / RE9; source default 0) | Optional C256 internal-stage ready queue (blocks 16–21 and 49–54) on the 900/1080 tiers, with matching `swin-persistent.hsaco`. Requires the wave-owned byte path and pooled allocations; graph/diagnostic layouts keep the old path. A 100 ms queue timeout aborts pending work, a bounded GPU serial replay restores the stage before consumers, and the instance disables persistence after observing the mapped error flag. Other stages retain their existing PDL behavior. Shared add-on / RE9 option; the RE9 runtime reads it from the environment its flags file sets. Bit-exact; offline 900 about -1.9%, 1080 about -0.6%. `0` restores the previous launches. |
| `DLSS5_HIP_INPUT_POLL` | `0` (source default; not in templates) | Experimental D3D→HIP handoff on the GPU: the game queue writes a marker (`WriteBufferImmediate`) and the HIP stream waits with `hipStreamWaitValue32` instead of the shared fence. `1` = own marker list per frame, `2` = marker recorded into the input-copy list. Start-up self-check and a 200 ms watchdog fall back to the fence path. Shared add-on / RE9 option (bridge header). Bit-exact, but the full-frame replay is 0.01–0.04 ms slower on both tiers (results/handoff-gpu-20260930), so it stays off. |
| `DLSS5_HIP_POST_SIGNAL_QUERY` | `1` (source default; not in templates; add-on and RE9 runtime, bridge header) | After the HIP network signals the D3D12 fence, one non-blocking `hipStreamQuery` makes Windows HIP submit the whole batch at once. Bit-exact; add-on replay −0.01…−0.12 ms per frame (results/outside-net-20261002). `0` turns it off (environment or flags file). |
| `DLSS5_NETWORK_1080_ROWS` | `1152` (all three templates; source default 1152) | Rows the 1080 tier (fixed `DLSS5_NETWORK_HEIGHT=1080` or chosen by `auto`) runs on. `1152` = NVIDIA's geometry (1080 + 72 reflected rows, ViT 30x18 tokens in a 32x20 grid), bit-exact with previous versions. `1088` = **compact, LOSSY, differs from NVIDIA's geometry** (1080 + 8 reflected rows, ViT 30x17 tokens in the same 32x20 grid, post shift unchanged; the geometry Daniel/mochizuki use): faster, the output changes over the whole frame (see `Development/results/geom-1088-20260930`). `DLSS5_NETWORK_HEIGHT=1088` selects the same geometry as a fixed tier. Shared add-on / RE9 runtime option. 900/720 tiers unaffected. |
| `DLSS5_NETWORK_FREE_RES` | `0` (all three templates; source default 0) | `1` = the network runs on the input's own size instead of snapping to the 720/900/1080 tiers: each axis is padded to a multiple of 64 (the width takes 64 more when both are multiples of 256; a 1088-row result becomes 1152, NVIDIA's 1080 geometry), the input sits at the top-left and the padding is a mirror image, the ViT grid is each axis /64 rounded up to 4. Overrides `DLSS5_NETWORK_HEIGHT`/`DLSS5_NETWORK_1080_ROWS`. Admits inputs from 320×320 up to a 3840×2176 processing surface without `DLSS5_FIT_LARGE`; outside that range the tiers (and `DLSS5_FIT_LARGE`) apply as before. 1920×1080 and 1600×900 inputs give exactly the tier output; other sizes change the output (no scaling: closer to NVIDIA — 1440p 35.9→46.4 dB, 4K 33.3→48.5 dB against NVIDIA's NGX output, all blocks, Style 0). Cost follows the processing pixels: 1440p 1.7×, 3440×1440 2.3×, 4K 3.6× the 1080 tier's frame time. HIP backend only (add-on and RE9 runtime). Read at network creation. Diagnostics: `DLSS5_NETWORK_FREE_PAD=WxH` forces the processing size, `DLSS5_NETWORK_FREE_EXTRA=w\|h\|0` the axis of the 256 rule. See `Development/results/free-res-20261002`. |
| `DLSS5_SKIP_BLOCKS` | empty = all 71 blocks (all three templates since 2026-10-03; source default empty in the add-on and the RE9 runtime) | Comma list of residual blocks to skip (each is replaced by a copy of its input). The default runs every block; together with `DLSS5_FAST_NUMERIC=1` this is 47.55 dB against NVIDIA (1080p single frame, Style 0). `42,43,46` = the previous default, kept as an optional speed-up: **LOSSY**, about 0.20 ms (900) / 0.32 ms (1080) less per frame, about −3.3 dB against NVIDIA (47.43 → 44.26 with the bit-exact path) plus an overall colour shift of about +0.15/+0.23 (1/255); structural, per frame, nothing carries over. An empty value removes the variable (both readers use `_putenv`), so empty and absent mean the same; the RE9 runtime before 2026-10-03 had `42,43,46` built in, so an empty line still skipped there. Shared add-on / RE9 runtime option, read when the network is created. `Development/results/default-swap-20261003`. |
| `DLSS5_FAST_NUMERIC` | `1` (all three templates since 2026-10-03; source default 0) | `1` = **fast numeric path, LOSSY**: the lossy fast-numeric module twins are loaded next to the normal ones (a missing `-fast` file falls back to the normal module with a stderr line; nothing is opened when the option is 0). Coverage since 2026-10-03: C32 + C64/C128 wave kernels (f32 activation/normalisation, no half rounding steps; softmax 1/sum by `rcp`) from `c32-wave1-fast.hsaco` / `c64-wave2-fast.hsaco`; ViT attention (bare-rcp denominator inverse, epilogue without the RTZ half round trip), ViT contract + projection (without the RNE half round trip) from `vit-stream-fast.hsaco`, and the C512 FFN projection (same) + decoder from `deep_fast-packed-fast.hsaco`. Offline (network-only bench, both sides skipping 42,43,46 like every previous fast-tier measurement): 900 about −0.09 ms, 1080 about −0.10 ms per frame, every ABBA round faster both tiers; against the bit-exact output 52.1 dB worst frame, 53.0–55.6 dB per sequence (`Development/results/fast-vit-c512-20261003`). Against NVIDIA (1080p, Style 0) 44.26 → 47.55 dB was measured with the c32/c64-only set; the ViT-deepened set's against-NVIDIA number is not re-measured. The C512 attention-projection f16-residual variant measured bit-exact but slower (not shipped). The approximation is numeric, so the error is carried through every following block and may build up in ways that can't be predicted scene by scene; nothing carries over between frames. Template default since 2026-10-03 together with all 71 blocks: against the previous default (skip 42,43,46, bit-exact path) about 0.12 ms (900) / 0.19 ms (1080) slower per frame, 44.26 → 47.55 dB against NVIDIA, and on motion about 3 dB closer to the bit-exact all-block output than the block skip (`Development/results/default-swap-20261003`). `0`/unset = bit-exact, the `-fast` files are never opened. Other values are reported and treated as 0. Shared add-on / RE9 runtime option, read when the network is created. `Development/results/fast-numeric-option-20261003`, `Development/results/fast-vit-c512-20261003`. |

| `DLSS5_MULTI_PASS` | `1` (all three templates; source default 1) | Multi pass: `2`/`3` run the whole network 2/3 times per frame, each pass fed the previous pass's final RGB (alpha 1) with the same history, seed and noise, like Magpie 0.6.8's DLSSNR Multi Pass; the style gets stronger with each pass. The network output is already the clamped [0,1] picture in the input's working encoding (post head = input RGB + residual), so the decode→encode round trip between passes is the identity and is skipped (only the encode pass's RGBA16F rounding is not repeated; the f32 output is fed as is). No per-pass parameters (Style/strength are the same for every pass). Cost is linear: offline whole network 900 7.0 → 13.7–13.9 / 20.5–20.7 ms, 1080 9.8 → 19.5 / 29.0 ms (about 1.95×/2.9×); outputs are reproducible (two runs hash-identical, no non-finite values) (`Development/results/multi-pass-20261003`). Extra VRAM: one (`2`) or two (`3`) RGBA f32 feed buffers of processing width × height × 16 bytes (1080 tier 35.4 MB each, 900 24.6 MB, 720 15.7 MB), allocated on the first multi-pass frame; the other intermediates come from the same pool as a single pass. Measured in the RE9 runtime (`rt_bench`, process VRAM): 900 tier 1407 → 1435 (2) / 1482 MiB (3), 1080 tier 1380 → 1491 / 1491 MiB. Adaptive ViT reuse (`DLSS5_VIT_ADAPTIVE`) is forced off while N>1 (its cache is per frame, not per pass). RE9 `GetTimings`/`net_gpu_ms` and `DLSS5_NET_TIMING` report the total of all passes. `1`/unset/empty = one pass, same code path as before (bit-exact). Other values are reported on stderr and treated as 1. Shared add-on / RE9 runtime option (network layer, `hip_reference_network.h`), read when the network is created; HIP backend only. Since 2026-10-03 (after this row's first version) the add-on also takes it from the hot reload (`DLSS5_HOT_RELOAD`, applied before the next network frame; same value = nothing happens) and from the hotkey `DLSS5_MULTI_PASS_HOTKEY`; the RE9 runtime still reads it once. |
| `DLSS5_MULTI_PASS_PREDICT` | `1` (all three templates; source default 1) | **LOSSY** third-pass prediction. Only when `DLSS5_MULTI_PASS=3` and this switch is `1`, run two real network passes and locally predict the third from the input and first two outputs. `0` disables prediction and runs three real passes; unset/empty defaults to 1. Only pass count 3 activates it; all other counts retain their existing path. Invalid values are reported and treated as 0. This is an approximation of our own full 3-pass output, with quality and speed requiring measurement; no NVIDIA exact claim. Shared add-on / RE9 runtime option (whitelisted). Add-on hot reload applies it before the next network frame alongside `DLSS5_MULTI_PASS`; RE9 reads it at network creation and needs a restart. Logs record both the requested option and whether 3-pass prediction is active. |
| `DLSS5_MULTI_PASS_SKIN_PROTECT` | `0` (all three templates; source default 0) | Skin-color protection for multi pass. With `1` and `DLSS5_MULTI_PASS>1`, blend the first real pass (`y1`) with the final pass (`yN`) using a skin-color heuristic mask. Mask core `m=1` preserves **exactly y1**; non-skin `m=0` preserves **exactly yN**; intermediate mask values blend the boundary. This is a color heuristic, **not semantic segmentation**: warm backgrounds may be selected and colored lighting may cause skin to be missed. The network input `x` is already in its sRGB-like shoulder working encoding; the mask does not apply another gamma transform. Default `0`/unset/empty and all single-pass runs preserve existing behavior. Invalid values report on stderr and use 0. Shared add-on / RE9 runtime option (whitelisted). Add-on hot reload prepares the kernel/resources before the producer wait and applies the switch before the next network frame; RE9 reads it at creation (restart required). Startup and hot reload logs include pass count, skin option and active state. |
| `DLSS5_MULTI_PASS_SKIP_BLOCKS` | empty (regular / Magpie / RE9 templates; source default empty) | Multi-pass skip: blocks skipped **only in passes 2..N** of `DLSS5_MULTI_PASS`, same list syntax as `DLSS5_SKIP_BLOCKS` (added to it for those passes); pass 1 always runs the configured network. **LOSSY** when set. Skippable here: C32 1–4/66–69, C512 23–30/40–47, ViT 31–38; the C64/C128/C256 blocks (5–22, 48–65) cannot be skipped with the production byte-stream pipeline. With 3 passes, current default (all blocks + FAST_NUMERIC=1), offline whole network: empty 21.1 / 29.8 ms (900 / 1080); `42,43,46` 20.7 / 29.3 ms, 43.9–46.0 dB; `31,32,33,34,35,36,37,38,40,41,42,43,44,45,46,47` (ViT + C512 up) 18.4 / 25.7 ms (−13%/−14%), 34.1–35.0 dB; `23`…`38,40`…`47` (+ C512 down) 17.4 / 24.3 ms (−17%/−18%), 33.2–33.6 dB. **The dB are against our own 3-pass all-block output, not against NVIDIA**; for scale, 3 passes against 1 pass is 35.0 dB. The ViT + C512-up set takes away much of what the later passes add (lighter, less contrast; 37.5 dB from 1 pass); the deep set is about as far from 1 pass as full 3 passes, in another direction (dark areas lifted). Structural, per frame, nothing carries over; the saving is small because the cost sits in the full-resolution C32/C64 chain. No effect at `DLSS5_MULTI_PASS=1`. An unparsable list, or a block this pipeline cannot skip, is reported on stderr and treated as empty. Shared add-on / RE9 runtime option (whitelisted), read when the network is created. `Development/results/multi-pass-skip-20261003`. |
| `DLSS5_MULTI_PASS_HOTKEY` | `F9` (regular / Magpie templates; source default F9; RE9 runtime: not applicable) | In-game key that cycles `DLSS5_MULTI_PASS` 1→2→3→1 starting from the pass count in effect. A press writes `DLSS5_MULTI_PASS=N` into `custom-config.txt` (the line replaced, else appended; the file created if missing; BOM and line ends kept) and the hot reload applies it within about a second (logged as `event=multi_pass_hotkey` and `multi_pass=N` in `logs\native-game-oneshot.txt`). Layer order still holds: if `native-game-flags.txt` also has `DLSS5_MULTI_PASS` it would win, so that line is rewritten too (stderr line); a `DLSS5_MULTI_PASS` system environment variable wins over every file (stderr line, the change does not apply). `F1`…`F24` or a virtual-key number (e.g. `0x78`); `0` = off; other values → F9 with a stderr line. Polled with `GetAsyncKeyState` once per network frame like F6/F7/F8, so it reacts while the game window is not focused too. Needs `DLSS5_HOT_RELOAD` on (default). Read once at start. Not pressed / off = bit-identical. The RE9 runtime has no hot reload and no hotkey. |
| `DLSS5_FORMAT_FALLBACK` | `1` (0.38 templates: regular / Magpie / RE9; source default 1) | Colour-format fallback table (`src/native_format_fallback.h`, after mochizuki 0.0.2.4). Colour formats outside the original table that the GPU decodes to float through a typed SRV — R9G9B9E5_SHAREDEXP (linear HDR), B8G8R8X8 (UNORM/SRGB/TYPELESS), R10G10B10A2 (UNORM/TYPELESS), R32G32B32A32 / R32G32B32 (FLOAT/TYPELESS), R16G16B16A16_SNORM, R8G8B8A8_SNORM, B5G6R5, B5G5R5A1, B4G4R4A4 — are accepted. Add-on pre-upscale route: one compute pass (`native_format_convert.hlsl`, ships in `native-game-tiled-assets`) converts the colour into a private RGBA16F texture that takes the unchanged RGBA16F route; FSR is handed that texture. RE9 runtime: the encoder's SRV reads the format and the private FP16 output route (RGB9E5's since 0.28) is used. Formats accepted before never reach the table (bit-exact). A rejected colour is logged with its format name (`native-pre-upscale.txt` / RE9 `PrepareFrame: colour rejected`). Post-upscale / Magpie / XeSS routes are unchanged (their output is written back into the game texture). A missing shader only turns the fallback off. `0` = original table. |
| `DLSS5_HOT_RELOAD` | `1` (0.38 regular / Magpie templates; source default 1; RE9 runtime: not applicable, strength is live in the OptiScaler menu) | At most once a second the add-on checks the last-write time of the three config files (default / custom / native, since 2026-10-03; before: native-game-flags.txt only); when any changed, `DLSS5_STRENGTH` (all add-on routes), `DLSS5_NOTICE` and `DLSS5_SHOW_FPS` (pre-upscale route's status line) and, since 2026-10-03, `DLSS5_MULTI_PASS`, `DLSS5_MULTI_PASS_PREDICT` and `DLSS5_MULTI_PASS_SKIN_PROTECT` (HIP network, before its next frame) are re-read and apply from the next frame; logged as `event=hot_reload` in `logs\native-game-oneshot.txt`. Strength `auto`/absent follows its startup/app default; removing a pass/prediction/skin key restores its built-in default (1/1/0), not the previous edited value. Network geometry, skip blocks, HIP/module/kernel switches, DIRECT_IO, PRE_UPSCALE, FIT_*, ASYNC, FRAME_STATS and FORMAT_FALLBACK are read once (they size buffers, load modules or change the network's numbers) and still need a restart. Unedited file = no change (bit-exact). `0` = never poll. |
| `DLSS5_IO_FUSE` | `0` (source default; not in templates; RE9 runtime: not applicable, it does not use NativeGameFrame) | Experimental, bit-identical: the decoder reads the network's f32 RGB output buffer directly (same f32→f16 rounding) and the separate neural texture pass is skipped. Plain sessions only (no temporal/history feed, no `DLSS5_OVERLAP`); otherwise ignored. Offline −0.004 to −0.035 ms/frame, but 900p p99 not better (results/input-slim-20261001), so it stays off. |
| `DLSS5_STYLE` | `1` (all three templates; source default 1) | NVIDIA NGX Style control, `0`/`1`/`2`, passed to the preprocess step as feature 6 = Style/128 (`dlss5_style_feature` in the C32/prefix modules, set by the host after each module load). `1` is the style the original runtime used in Stellar Blade (captured 2026-09-06) and what every package so far had built in; `0` is NVIDIA's default and matches its reference output (1080p single frame, full 71 blocks 47.43 dB, release recipe 44.26 dB, against 24.06 dB with Style 1); `2` the third style. RE9 runtime: read from its flags file since the build after 0.39 (0.39's runtime only took it from the system environment). **Integrator note:** read once when a session is created (with the module load), not hot-reloaded; an environment variable of the same name wins over the flags-file line; the C32/prefix modules must be 0.39 or later (older ones silently stay at Style 1), and the fast-tier c32/c64 modules in the lab are older and ignore it. |
| `DLSS5_NET_TIMING` | unset (not in any template) | Diagnostic: `1` records hipEvents around the HIP network every frame (the same span the RE9 runtime reports through `GetTimings`/`GetStatus`, where it starts at the first `GetTimings` call). The regular add-on never reads the value back, so leave it unset there. Bytes unchanged. |

## Historical packaging notes

These describe older packages, not current defaults or build instructions.

`Development/native-game-flags.txt` is an early test configuration; `scripts/game-flags.txt` and `magpie-flags.txt` belong to the old DX12 route and are not current HIP release defaults.

Version 0.27 used `Development/tools/package-027.ps1` for all three packages, reading templates through `ConfigDirectory`. Regular packages were extracted from verified historical ZIPs, not directories that might have been modified by running the applications. REFramework used the verified complete 0.26.1 package as its baseline.

Version 0.28 used `Development/tools/package-028.ps1`, building from file-verified 0.27 ZIPs. Magpie and regular OptiScaler used their respective flags templates. RE9 overlaid the baseline OptiScaler.ini with re9-presr.ini and removed the ineffective old native flags and post-present add-on. Its historical network default skipped 42,43,46 with reuse disabled; F8/SHOW_FPS/NOTICE did not apply. Detail/colour strength was controlled in the OptiScaler menu, range 0..1. Bilingual package instructions came from scripts/package-notes/. Packaging did not read personal game configuration.

Version 0.28.1 rebuilt only the RE9 package through `Development/tools/package-0281-re9.ps1`, with the boundary/recovery fix candidate 74b8a67; the other packages remained at 0.28. After validation, the local complete RE9 0.28 package and its README download entry were removed.


### Unreleased 900-tier normalization source update

With FAST_NUMERIC=1, an available `c32-wave1-fast-norm900.hsaco` can be selected for processing 1600×960, MP1, graph off and experimental history off. Other modes retain their original route. A missing or incomplete optional module falls back. This preserves the existing math and requires no extra setting. AE correctness is validated separately from AE-off performance measurements.

### Unreleased scoped HIP submit pulse

`DLSS5_HIP_SUBMIT_PULSE=auto` is the new internal default. Auto applies only to the verified Windows gfx1201/Runtime7 driver32.0.31007.2048, processing1600×960 or1920×1152, current full71 FAST1/MP1/AE0/graph-off/no-active-history recipe, and the actual ordinaryC256Down boundary before C512. It creates one owned timed event and records it there; it never enables timing getters or adds a query/wait in the frame path. `0` disables it. `1` is an explicit experiment on the samearchitecture/runtime/topology and may admit another driver; the log marks that driver unvalidated and no speed claim follows. gfx1200 and other scopes retain the prior path.

Driver lookup failure, missing required active recipe exports, or event creation/recording failure disables the pulse while preserving the old network attempt. OptionalSP init_pair is not mandatory: the measuredstock profile has no such export; auto rejects a differentSP pair recipe. Device/runtime failure is not guaranteed recoverable. Per-frame runtimeeligibility is checked at the known ordinaryDown boundary, not from cumulativePDL count. Resources retire on the owningdevice/stream; failed cleanup retains the owner context. Existingconfiguration values and packagefiles are unchanged. This source change remains local pendingproduction compatibility/resmoke and combinedvalidation.

## Optional Fast History experiment (default off)

Set `DLSS5_TEMPORAL_MODE=1` in `custom-config.txt` and restart the game. This consumer supports HIP addon and standalone runtime, a full network viewport, `MULTI_PASS=1`, `HIP_GRAPH=0` and `OVERLAP=0`. The standalone runtime explicitly uses screen-coordinate history without motion/depth compensation. Disable Fast History and restart before selecting MP2/3; F9 cannot switch it to multiple passes. Prediction preferences are inactive in MP1.

Declare `DLSS5_TEMPORAL_MV_UNJITTERED=1` only for genuinely unjittered motion vectors. Declare `DLSS5_FAST_HISTORY_DEPTH_INVERTED=0` for conventional depth or `1` for reversed depth according to the game; there is no guessed default. Without trusted declarations, static fallback rejects history using raw-color change; it cannot compensate motion or reliably detect occlusions, and may ghost. Actual early-frame state is written to `fast-history-mode1.log`. Set `DLSS5_TEMPORAL_HISTORY_EXPERIMENT=0`: the two history modes are mutually exclusive. Existing `DLSS5_FAST_TEMPORAL=1` is a legacy sampling optimization, not activation of this new feature. Normal configuration precedence still applies, including legacy native-game-flags and environment overrides.

Matching C32 logit exports for the actually selected FAST/RTZ/norm900 modules and `post70-history-head.f16` beside the model assets are required. An older package cannot gain the complete feature by changing flags alone. See [interfaces and row extraction](../Development/integration_interfaces.md#addon-fast-history). Default0 does not depend on these new assets.

This separate approximation uses FP32 feedback and depth/raw/black-output validity heuristics; it differs from NGX and the0.41-a reference experiment. It changes output and may produce ghosting. Numerical fixtures do not establish game visual acceptance. Its cost has not been measured here and must not inherit the reference experiment's timings. Approximate ViT reuse is gated for the session without changing the user's preference.

Fast History currently admits motion textures whose mip-zero dimensions exactly
match the active render width/height. Padded or display-resolution motion
layouts are unsupported: their missing context/active-extent contract resets
history and uses current-frame NR. Depth may be padded because sampling uses
the declared render extent.

当前 Fast History 只接收 mip0 尺寸恰等于实际 render 区域的运动纹理；带padding或显示分辨率MV缺少上下文/有效区域合同，会重置历史并用本帧NR，不猜测采样区域。深度按声明的render区域采样，可保留分配padding。

## Single temporal mode selector / 统一时域模式

`DLSS5_TEMPORAL_MODE=0` is the default: unchanged NR output with no new temporal resources. `1` selects TheAutomatic Fast History (the existing approximate PR12 implementation, row/logit exports required; undeclared motion/depth uses explicit static fallback); `2` selects an independently implemented low-frequency residual EMA at the final NR output, no row or new NN exports. Both active modes require MP1 and cannot combine with `DLSS5_TEMPORAL_HISTORY_EXPERIMENT=1`. Restart to change modes. An explicit MODE value, including0, wins over legacy `DLSS5_FAST_HISTORY`; only absent MODE maps legacy FAST_HISTORY1 to mode1. Invalid/empty MODE is rejected.

Mode2 operates in the codec's encoded NR working domain, not Magpie's display RGB. It retains this frame's high-frequency residual and smooths only guided low-frequency residual over approximately80ms. With a declared valid render-sized unjittered MV it may compensate motion; otherwise it explicitly uses screen coordinates plus conservative original-colour rejection (no invented zero-MV validity, no depth guess). Ghosting/quality and real-game cost remain experimental. The first implementation is synchronous to protect buffer/control lifetimes. It gates approximate ViT reuse for the session without rewriting preference. Runtime input identity is unknown: no duplicate-frame skipping is inferred.

唯一主开关 `DLSS5_TEMPORAL_MODE`：0关闭（默认）、1原TheAutomatic Fast History、2独立实现的低频时域滤波。显式MODE含0压过旧FAST_HISTORY；缺MODE才兼容旧1。两种开启档都要求MP1，不能与reference实验叠用，切档需重启；非法/空值拒绝。Mode2在NR编码工作域而非显示HDR域，仅平滑低频修正、高频留本帧。可信声明的MV可补偿，否则明确用屏幕坐标静态颜色门，可能拖影，不伪造运动/深度合同。当前同步原型优先资源安全；观感/游戏性能需实际试用，旧History耗时不能套用。
