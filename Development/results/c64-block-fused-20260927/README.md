# C64～C256 整块融合 / 持久化：对照 mochizuki DLSSNR-AMD，得到 W2_PACK8（2026-09-27）

参照：<https://github.com/mochizuki0323/DLSSNR-AMD> @ 4f62a8a（Vulkan compute，Linux RADV/ACO 为主）。实验 `HIP/experiments/c64-block-fused`。

## 1. 对比笔记

**它报的数（9070 XT）**：整网 1080p Linux 6.0 ms / Windows 9.4 ms（同一套着色器，Windows 驱动编译器对大核慢）。`nr_graph.cpp` 注释里的各宽度内核总时间（1080p，合并后）：C64 0.71、C128 0.85、C256 0.99、C32 0.93 ms。我们（family-ledger-wave-owned-20260926，1920×1152）：C64 1.83、C128 1.79、C256 1.86 ms。按 Windows 编译器 ×1.57、行数 ×1.067 折算，C64/C128/C256 仍差约 1.3～1.6 倍。

**"整块融合"我们已经有了**：0.31 的 wave-owned 路径里 C64/C128 每块就是一次 `c64_wave2` 派发（norm→QKV→窗口注意力→投影→残差→FFN→残差），一 wave 管一个头的 64 token，中间结果不回显存；C256 是 FFN/QKV + `c256_attn_wave` 两次。所以差距不在"融不融"。

**它单层快在哪**：
- **转置排布**（`fswin_t.comp` L151-176）：矩阵全存成 [特征][token]，权重当 A、激活当 B。gfx12 WMMA 的累加器分量排布正好是 B 操作数的排布，所以只要"累加器的行号 = 下一次乘法的收缩维"，上一步的结果能直接当下一步的操作数，不经 LDS、不拍 barrier；LDS 只剩 K/V（C=32 时 6144 B 对 20992 B）。残差变逐元素加，Q/K 的 L2 归一化和 softmax 分母变成列归约（lane 内 8 个 + 一次 shuffle）。
- **省 VALU**：它记下"RDNA4 上 FP8 WMMA 与 VALU 不重叠，连跨 wave 也不重叠；帧时 ≈ WMMA + VALU + load + 空闲"，于是一路删 VALU（饱和转换、量化模式、wave-uniform 地址标量化）。
- **持久化**：同一级连续几层一次派发，(layer, window) 按层优先编号从一个原子计数领取，消费者只自旋等它真正依赖的 4 个生产者窗口（移窗只依赖相邻 4 个），无死锁（编号小的一定已被领走）。它实测：C64/C128/C256 合并整帧 8.73→8.08 ms（主要来自 C256 1.40→0.99），C32 合并反而更慢，不用。这和我们的 PDL 任意序 + 逐 tile 旗子是同一个思路，只是它做成了单派发。

## 2. 逐位可行性

**转置本身逐位可行**：探针 `wmma_transpose_probe`（2000 组随机，含大数/小数/抵消，K=256 连续累加，初值 C 非零）：`wmma(Y,X,Cᵀ)` 与 `wmma(X,Y,C)ᵀ` 在 fp8 和 f16 上各 512000 个值 **0 个不同**。gfx12 的 A/B 寄存器排布相同，交换参数就是转置，硬件归约对 A/B 角色对称。我们的内核里本来就混用两种顺序（`q[ci]` 的 part 2 就是 `(a,b)`）。
风险在逐元素和归约：`w2_serial_norm` 是 lane 内顺序加 + `ds_bpermute`，转置后要逐位就得复刻同一加法顺序（可做，但要一步步对）。

**我们内核的 VALU 大头**（`c64_wave2_bi_bo` 静态 ISA：WMMA 150 条对 VALU 3931 条）：每量化一个 E4M3 字节约 6 条——med3 clamp、`v_cvt_pk_fp8_f32 v,x,x`（成对指令只用一半）、移位、and、`cmp_neq(x,0)`+`cndmask`（±0 → +0）、or 拼字。8 个值一个片段，每个量化点都这样。

## 3. W2_PACK8（本次实现）

`hip/wave_owned_mh.inc`，宏 `W2_PACK8`（默认 0，默认展开与原代码逐记号相同）：同样的字节，两值一条 `v_cvt_pk_fp8_f32` 直接写进片段字的高/低半；clamp 后 `+0.f` 把 -0 变 +0，其余输入（含 NaN、±Inf、下溢成 -0 的小负数）不变——等价于原来的 `|x|==0 ? 0 : byte`。`+0.f` 放在 clamp 之后，不会与前面的乘法收缩成 FMA。覆盖 `wave_owned_mh.inc` 的 8 个量化点，C256 注意力体也从这个文件抽取，一并生效。

静态 ISA（gfx1201，W2_PACK8 0 → 1）：

| 核 | 指令 | VALU | cvt_pk_fp8 |
|---|---|---|---|
| c64_wave2 | 6249→4650 | 3987→2783 | 384→240 |
| c128_wave2 | 6874→5349 | 4132→2939 | 384→240 |
| c256_wave2 | 7506→5967 | 3988→2832 | 384→240 |
| c256_attn_wave | 2219→1875 | 1121→861 | 64→40 |

VGPR 不变。W2_PACK8=0 编出的 c64-wave2 与 0.32 装的模块代码段相同（gfx1201、gfx1200 都核过，`hip/compare-modules.py`）。

**逐位**：7 组 × 12 帧（900/1080 静态与运动、720 运动、900/1080 历史帧）全部逐帧 hash 相同。

**计时**（生产 host，千帧去前 200，槽 0/3 基线、1/2 候选；两批）：

| 档 | 批 1 | 批 2 |
|---|---|---|
| 900 | 10.693 → 10.277（−0.416，−3.9%） | 10.774 → 10.377（−0.397，−3.7%） |
| 1080 | 14.995 → 14.385（−0.611，−4.1%） | 15.032 → 14.426（−0.606，−4.0%） |

测试时 9070 上开着 Magpie 进程（未在缩放），两批一致。

## 4. 结论与下一步

- W2_PACK8 逐位、整网 −4%，建议进下次发包：`hip/build-modules.ps1` 的 c64-wave2 配方加 `W2_PACK8 1`（模块替换即开关，不需要新 flags 键，add-on 与 RE9 runtime 都读同一个模块）。
- 同一打包法还没推广的地方：C32（`wave_owned_c32.inc` / `c32_fused_ffn_attention.hip` 的 `fp8()`/`F()`）、C256 FFN/QKV（`multihead_fast_padded.hip` 的 `q8_fused_round` 调用点）、C512/ViT（deep）。C32 份额最大（34%），先做它。
- 转置排布（去 LDS 往返）逐位可行，但要逐步复刻归约顺序，是下一阶段的大活；持久化单派发与我们的 PDL 同源，收益主要在 C256，排在转置之后。
