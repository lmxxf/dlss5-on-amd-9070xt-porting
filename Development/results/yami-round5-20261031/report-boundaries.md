## 9. 对表 3.0 / 3.2 的逐家族交代

表 3.0 的窄探针基线为 `1005424b`，还没有 R4-A。不能把其中 P0 的 452.26 / 276.68 / 202.26µs 当作 `b60e6a8c` 上仍然可收割的时间。旁路同时破坏数学和依赖链；旁路差值也不是可实现的无损收益上界。

|家族|本轮实际追到哪里|仍未证明的部分|
|---|---|---|
|C32|当前基线 R2-D 组成对照；概率转换 intrinsic 与保留汇编顺序两种 MODE 外提；完整帧实测|没有穷尽转换的排程、WMMA 归约与跨阶段融合，负结果仅约束这些实现|
|C64/C128|C128 中间四层持久阶段实装，数学/Gold/实际任务路由通过，两个 Original 档稳态回退；另对 C64/C128/C256 共享概率转换做免 MODE 分支，并测试宿主查找缓存|C64 没有新的专用内核排程搜索；C128 的负实验不能封死 C64/C128 全族|
|C256/SP|C256 非 SP 路径随共享概率免 MODE 分支实测；保留 SP 生产路径并核对实际网格与任务模型|SP 内部未引入概率分支，C256 的融合与排程也没有穷尽；该族不能标为已达上限|
|C512|倒数 8→1、概率输入去冗余 clamp 分别隔离实测；clamp分支正值通过独立长验证并继续做Small1080集成|没有穷尽 split FFN、QKV/AV 之间融合和寄存器排程|
|ViT|成对映射根因修复、两种等价取值实现、原生 RTZ、三种宿主接法、核内 shape 分支、缓存×新核四臂、独立长验证与代码布局对照|已证明一个局部核更快；未证明该局部收益能在生产整帧稳定兑现，也未穷尽 QKV/project/gather|

表 3.2 的 ACO 阶段差用于定位关注点。本轮没有重新跑同批 ACO，更没有证明两条路径所有数学与计时边界等价，故不能把差额直接记为“剩余无损收益”或据此认定某个优化一定有效。

**明确保留 Open：C64/C256 专用排程、C128/C512 融合与 ViT 局部收益的稳定整帧兑现。** 本轮没有把用户要求的“全部收益抠干并证明上限”完成。当前能成立的结论是各个已测试候选的实测裁决；不能从若干失败分支推出全局不可改进。

## 10. 测量纪律和适用范围

- 原始 R2-D 批运行期间上传过后续文件，存在远端 CPU/I/O 干扰可能。追加了一次预先固定的三档三轮无其他远端操作复核，见 `quiet-confirm-plan.md`。两批均保留，单独列数，不合并成更好看的结论。
- 本地分析和编译运行在 `spark-3a10` Linux 主机，GPU 实验在独立 Windows `amd9070` 主机；没有把本地 CPU 编译当作 GPU 主机上的并行工作。除明确隔离的复核批外，未对整个长会话的远端后台负载做连续遥测，因此不声称绝对无系统噪声。
- Gold 七档是固定输入、当前 FAST1 参考的逐位一致性。它没有穷尽所有动态场景、AE/FAST0 配置或数学输入。没有候选被晋升时，不把实验 Gold 外推成发布认证。
- 普通每臂 960 帧的 pooled p99 是经验尾部分位数，帧间可能相关，三轮也不是显著性检验。“3/3 赢”只是筛选条件。ViT 曾满足短批条件但在事先写定的更长验证中失败，正说明不能只取最漂亮的一批。
- 所有时间表为原始 `out.csv` 的 `wall_ms`，100MHz 阶段计时另表单列。没有用启动日志中包含冷启动的平均时间替代稳态值。
