## 2. 点名问题一：ViT Gold 失败已定位并修通

根因是当前 COMGR 对半精度向量分量左值直接执行 `__builtin_bit_cast(ushort, x[e])` 时取错元素，读成元素 0。最小 GPU 复现为 1,024 组 × 8 分量：直接写法 7,168 处错误；先复制到标量再 bit_cast 为 0；整数半字提取为 0。没有发现 af0/af1 高低半字颠倒。证据：`vector_element_probe.hip`、`vector-element-verdict.json`。

修复后从 `pair_exp[e/2] >> (16*(e%2))` 提取半字，再沿用原来的标量 half→float 路径。七档各三帧、两臂合计 42 帧 Gold 通过。正确版本的 vfrag/qkfrag 是 57/56 VGPR（原 61/60），不是错误实现的 55/54；普通 attention 仍为 68，private 均为 0。整数提取和标量临时变量两种修复的函数字节与 metadata 相同，未重复跑同一内核。

100MHz 实时钟中 attention 阶段：Original1088 −10.200µs、Small1080 −11.103µs，均 3/3 轮；驱动 occupancy API 对 stock/fixed 两种 qkfrag/vfrag 均报告 block32 时 64 blocks/MP。VGPR 数下降没有在这项 API 查询中跨台阶。

完整 Frame 没有自动兑现全部局部收益。后续原生 RTZ、追加后缀、常量名称、句柄绑定、核内 token 分支、缓存×新核四臂和布局控制都实际执行。最终收窄 ViT 句柄版本的一次预注册长验证 mean +2.138µs，不能采纳。见附录及 `pair-qualified-long-statistics.json`。

有效追踪的 score 相同而概率不同；trace3 的 half 读回本身用了有问题的向量分量 bit_cast，因此那列“0差异”不作正确性证据。trace2 源文件/记录步长不一致已作废保留，见 `first-divergence.json`。

## 5. 新的分母归约分支：正确性证明与真实筛选

Swin 指数映射产生正的 normal binary16，尾数低五位为零。设最小 half 指数字段为 E，则所有输入都是 q=2^(E−20) 的整数倍。正数求和若低于 2^24q=2^(E+4)，每个部分和都能由 FP32 精确表示。computed sum 低于这个二次幂阈值时，不可能曾越过阈值再被正数加法舍回阈值下方，因此可以据此安全判定。先用全域的 sum<32 快判，否则计算局部最小指数；wave ballot 要求所有 lane 满足条件。不满足就执行原来的四次串行 WMMA。该前提仅用于指数值，不用于平方范数。详见 `guarded-dot2-proof.md`。

测试了串行 dot2、四独立累加器 dot2、两累加器 WMMA、四独立 WMMA。COMGR 与生产 LLVM23 各四组，每组 1,048,576 个 lane 输出对照，含近 24-bit 精度边界、32±2^-19 的 CPU oracle、非对称与宽范围数据。八组 guarded diff、oracle diff、覆盖/重复分母/配对错误均为 0。相同输入跨实现/编译器重复使用，8,388,608 是比较次数，不是独立向量数。无保护重排出现大量差异，不能删除回退。

四候选各七档 Gold 通过。把原求和挪入 QK 生成循环的第五种尝试，最终 `.text/.rodata/.data`、函数字节/地址及 metadata 与基线一致，仅符号字符串/hash 表不同，因此没有重复 GPU 计时。

## 7. 回归、构建与证据完整性

基础组合已完成 15 组配置、100 对输出文件，全部 0 bit-diff：FAST0、AE配置、MODE1、F9、free，以及真实 temporal=1 的 AE计算→复用→失效/到期。四组 adaptive.csv 两臂逐字相同。MODE1 测的是无有效深度/运动元数据的静态回退路径；原 seed 递增路径已配对验证，另外固定 seed=0 与逐帧 reset 对照，frame0相同、frame2–5不同，确认历史反馈真的影响输出。

旧 history 测试器已被清理，故从当前源码新建了明确的变输入 harness，两臂同一 SHA；没有冒称恢复了旧二进制。MODE1 的实际路径是 fast_history，首次使用 legacy r.temporal 的错误诊断门已纠正并保留失败记录。

最终所选 `minimal` 载荷另外完成 20 组配置、138 对文件逐位检查，包含960档的FAST0、真实AE、MODE1及F9切换；全部配对0bit-diff。详见 `final-configuration-verdict.json`。

最终四候选各80个对象有精确的扁平源 SHA→产物来源映射；源未变才复用基线，源变的编译单元重建。gfx1201 的代码/数据/地址/metadata 匹配各已测候选；gfx1200 的运行代码匹配基线，feature guard 不启用新优化。符号标识会改变对象 hash，不等于执行代码改变。

构建核对发现并修复了一个继承的架构差异：C512 deep 在 gfx1200 用 max-ilp，gfx1201 用默认 COMGR 调度。两种编译产物与原基线逐函数比较确认此事；PowerShell 配方与 Python 构建工具现在明确保留该策略。错误选项的产物留档，但没有进入性能测试。见 `canonical-artifact-ledger.json`。

早期清单没有 pin 所有输入 fixture，因此后来采集的输入 SHA 不冒充早期预校验；那些批次有固定输出 Gold。新的资格批在运行前 pin 实际输入、完整资产树和模块。R2-D 首批上传干扰疑点用预注册安静复核处理；prob-asm 首批校验错目录的批次保留为未获资格，统计前固定重跑并加固执行器。

所有 GPU/RTC 任务使用游戏空闲检查、原子 gpu.lock、磁盘余量门和看门狗。最终清场见 `final-status.json`。没有通过挑选较好轮次替换原数据。

## 8. 上限判断与任务边界

已闭环用户点名的 ViT 错误定位/七档 Gold/时钟与ABBA、当前R2-D组成选择，以及动态计数修正；也实际推进了上述新分支。**“全部收益已经抠干”的证明没有取得。** 当前结果既没有覆盖全部调度/跨层组合，也没有给出与实测耗时贴合的硬件下界；不能用一批负实验或保守措辞签发上限证书。

Round4 表3.0的窄探针仍以1005424b为基线，不能把其P0差值当成b60尚存收益；破坏性旁路同时改变依赖和数学，也不是可兑现无损收益上界。表3.2的ACO差距可用于找目标，本轮未重新测同批ACO，也没有证明两路径全部数学与计时边界等价。
