## 1. 物理根因剖析：K6 `SubmitPulse` 漏网之鱼、K2 耦合真相与 `ffn8` 同址读写安全边界

1. **`PulseRejectMask` 遗漏 `Original 1088` 与 `Small` 家族（分支 K6）**：
   - 在 `hip_reference_network.h:1114, 1137` 中，`SubmitPulse`（在编码器 `ordered Down(22)` 后、`C512` 首块前记录一次 `hipEventRecord` 触发 ROCm AQL 队列提前向硬件发车，消除 CPU 入队 152 个核期间的 GPU 空泡）自 `2026-10-06` 引入时，硬编码了 `!small_active` 以及 `!((W==1600&&H==960)||(W==1920&&H==1152))?16384u:0u`。
   - 这导致 `Original 1088`（`1920×1088`）始终因 `init_reject_mask=16384` 被拒之门外；同时 `Small` 模型虽然同样在 `g=2` 结束时执行 `ordered Down(22)`（`pulse_ordered_down_c256 = true`）并抵达 `C512_encoder_start` 站点，却被 `!small_active` 和 `at_site&&!SwinRunActive()?1048576u:0u` 一刀切拦截。
2. **揭开 K2（`w16_fb8`）在 `original1088` 上从 `+230 µs` 逆转为 `-25 ~ -47 µs` 的物理机制**：
   - 在 Step 2 与 Step 3 中，K2（`split_projection_frag_w16_nof32_bskip` 省去 `4.42 MB/帧` `ffn` FP32 死写 + 非转置 `mh_attention_project_frag_c512_w16_u4_fb8_bout` 93 VGPR）在 `original960` 上 9/9 轮稳赢 `-25 ~ -28 µs`，而在 `original1088` 上却慢 `+229 ~ +243 µs`。
   - 原因正是：此前四档测试中唯有 `original960` 开启了 `SubmitPulse=1`！当 `original1088` 处于 `SubmitPulse=0` 时，CPU 端连续入队全部核函数后才一次性发车，C512 块省去 `ffn` 写出改变了整帧 AQL 批次与 D3D12 共享队列交错时的 L2/L3 驱逐相位；**一旦在 `original1088` 上开启 `SubmitPulse=1`（提前发车前段 `C32..Down(22)`），K2 在 `original1088` 上立即释放出与 `pure.exe` 一致的纯正加速（使 `original1088` 总加速达到 `-119.50 ~ -159.28 µs`）！**
3. **`w16_fb8` 保持 `if(!fb8&&!w16_fb8)ffn8.reset();` 独立分配（修复跨工作组读写同址竞态）**：
   - 在 Step 5 的 241 帧纯 NN `pure.exe` 连续压测中发现：若在 `mh_attention_project_frag_c512_w16_u4_fb8_bout` 启动前提前调用 `ffn8.reset()`，`NewPad16` 会将输出 `result` 分配在 `ffn8` 同一地址；由于 `ffn8` 是 `[16 token × 32 channel]` 瓦片布局而 `result` 是 `[token × 512]` 行主序布局，同一 16-token 行内的 8 个列分块工作组（`col = 0..448`）在 GPU 高频异步调度下可能发生跨工作组覆写尚未读取的 `ffn8` 字节。
   - 恢复 `if(!fb8&&!w16_fb8)ffn8.reset();` 后，`ffn8` 与 `result` 严格异址，36 个 NMMN slot（每 slot 241 帧）与七档 42 帧 Gold、七档 21 轮 ABBA（每 slot 240 帧）全部 100% `0 bit-diff`（`raw_bitdiff=0`），且 `original1088` Frame ABBA 加速进一步扩大至 **`-159.28 µs (-1.84%, p99 -180.60 µs)`**！
4. **最终生产方案 `k6c3` 三项核心合入**：
   - **`SubmitPulse` 扩围（K6）**：Original 允许 `1600×960`、`1920×1152`、`1920×1088`；Small 允许 `1600×1024`（`small900`）、`1344×768`（`small720`）、`896×512`（`smallwindow`），排除 `small1080`（避免 5.36 ms 短网中途拆包开销）。
   - **`w16_fb8` 精准作用域（K2-Scope）**：`HIP_VIT_INTER_BYTE` 默认设为 `31`（保留 `NR_VIT_INTER_BYTE` / `DLSS5_HIP_VIT_INTER_BYTE` 环境变量覆写回退能力），`C512W16Fb8ShapeEligible()` 精确限定为 `(W==1600&&(H==960||H==1024))||(!small_active&&W==1920&&H==1088)`，同时启用构造函数 `InitC512Cache()` 零开销缓存。
   - **`c64/c128_wave2` 优化（K5）**：`c64/c128_wave2_up_lb_sh` 折叠首 barrier 前 `qt` 循环（净砍 `-1,055` / `-977` 条指令）+ `c64_wave2` 全系压入 `189~191 VGPR`（8 waves/SIMD = 4 WGs/CU）。
