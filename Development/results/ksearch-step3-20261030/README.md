# K-Search Phase 3：K2-Fix 宿主与内存池隔离、分支 K4（`sp_run256_w16`）与分支 K5（`c64/c128_wave2`）实装及 ABBA 门禁（2026-10-31）

**总结论：三个候选分支（K2-Fix / K2-Fix2 宿主零开销缓存 + 就地复用 `ffn8`、K4 `sp_run256_w16` 开启 `W2_QKV_FUSE` + `W2_HOIST_LOADS`、K5 `c64/c128_wave2_up_lb_sh` 折叠首 barrier 前 `qt` 循环 + `c64_wave2` 全系压入 `<=191` VGPR = 8 waves/SIMD）全部通过七档 42 帧 Gold `0 bit-diff`（`invalid=0`）。其中 K5 在四档 3 轮 4-slot Frame ABBA 稳态门禁中实现四档 mean 全负（`-1.44 ~ -4.51 µs`），但幅度处于噪声带内且两档仅赢 2/3 轮、两档 p99 微退（`+13.7 ~ +18.7 µs`）；K2-Fix/K2-Fix2 与 K4 则未获全局净收益。按严格门禁纪律，三者均判定 `STOP -> Eliminated`，生产基线保持 `8a9c60fd` 不变。**

## 1. 分支 K2-Fix / K2-Fix2：彻查 `original1088` / `small1080` 在 `mode=31` 下端到端回退的真正物理根因

### 1.1 宿主开销排查与内存池 + L2 驻留真相
针对上一轮 K2 在 `original960`（`submit_pulse=1`）净快 `-25.64 µs`（3/3 轮）、但在 `original1088` / `small1080`（`submit_pulse=0`）反慢 `+238 µs` / `+57 µs` 的现象，本轮依次构建并实测了两个宿主级修复变体 + `DLSS5_GAME_PROBE=1` / `DLSS5_HIP_MEMORY=1` 探针：
1. **`k2fix`（编译期默认 `HIP_VIT_INTER_BYTE=31` + 构造函数一次性缓存 `InitC512Cache()` 布尔标志，彻底消除运行期 `getenv` 与每块 `HasFn` 查找）**：
   - 七档 42 帧 Gold：`0 bit-diff`，`invalid=0`。
   - 硬件实时钟探针（3 轮 ABBA）：`original1088` C512 双核合计 **`-17.19 µs`**（3/3 轮），纯 NN 全网 **`-24.13 µs`**（3/3 轮）；`small1080` C512 双核合计 **`-6.28 µs`**（3/3 轮）。
   - 四档 Frame 3 轮 ABBA：`original960` 净赢 **`-27.99 µs`**（3/3 轮，p99 `-9.56 µs`），`small900` 净赢 **`-12.71 µs`**（3/3 轮，p99 `-13.32 µs`）；但 `original1088` 仍慢 **`+243.01 µs`**，`small1080` 仍慢 **`+54.01 µs`**！这证明回退并非来自 CPU 端的 `HasFn` 或 `getenv`。
2. **`DLSS5_HIP_MEMORY=1` 内存池对比与 `k2fix2`（恢复 `ffn8.reset()` 就地复用 `1.00 MiB` 缓冲区）**：
   - `DLSS5_HIP_MEMORY=1` 揭示了一个隐藏的缓冲区分配差异：在 `CompactC512Body`（`hip_reference_network.h:798`）中，基线（`mode=15`）在 `c512_qkv_attention_compact_w16` 之后立即执行 `if(!fb8&&!w16_fb8) ffn8.reset();`，随后 `NewPad16(valid, 512, byte_out=true)` 为 `result` 分配 `1.00 MiB` 缓冲区时**原地复用了刚释放的 `ffn8` 缓冲区**（全网池 `27 tensors, 260.9 MiB`）；而当 `w16_fb8=true`（`mode=31`）时，`ffn8` 未在 `NewPad16` 前释放，导致额外分配第 28 个张量（`28 tensors, 273.8 MiB`）且 `result` 与 `ffn8` 异址乒乓。
   - 在 **`k2fix2`** 中，我们在 `NewPad16` 前保存 `void* ffn8_ptr = P(ffn8); ffn8.reset();`，使 `result` 100% 原地复用 `ffn8` 地址，池张量数与地址与 `mode=15` 完全一致：
     - 七档 42 帧 Gold：`0 bit-diff`，`invalid=0`。
     - 硬件实时钟探针（3 轮 ABBA）：`original1088` C512 双核 **`-18.88 µs`**（3/3 轮），纯 NN 全网 **`-15.42 µs`**（3/3 轮）；`small1080` C512 双核 **`-6.47 µs`**（3/3 轮），纯 NN 全网 **`-6.97 µs`**（3/3 轮）。
     - 四档 Frame 3 轮 ABBA：`small1080` 的退化从 `+54.01 µs` 大幅收窄至 **`+24.97 µs`**（p99 反超 **`-63.77 µs`**，第 3 轮净快 `-18.25 µs`），证明消除乒乓缓冲区在 Small 1080p 上追回了 `~30 µs`；但在 `original1088` 上仍慢 `+229.38 µs`。
3. **跨核 L2 驻留耦合的物理机制（为什么 `pure.exe` 快 `-30 µs` 而 `frame.exe` 在 `1088/1080` 上慢）**：
   - 在 `pure.exe`（纯 HIP 流，无每帧 D3D12 `Restore` 纹理拷贝和 `encode/decode` 抢占 L2）中，GPU Infinity Cache（64MB L3 + 4MB L2）全帧专供 NN 使用，因此消除 `4.42 MB` `ffn` 死写稳定净省 `-24 ~ -34 µs`。
   - 而在 `frame.exe` 的 `1920×1088` / `1920×1152` 档位（`submit_pulse=0`，每帧与 D3D12 共享队列交错执行 `CopyTextureRegion + encode + decode`）下，16 个（或 4 个）C512 块在 `split_projection_frag_w16_bskip` 中写出的 `ffn` + `ffn8` 组合恰好维持了 `c512_qkv_attention_compact_w16` 与 `mh_attention_project_frag_c512_w16_u4_bout`（32 条跨 32B 步长的 `global_load_u8` vs 连续列步长的 `global_load_b32`）在跨队列提交窗口内的 L2/L3 预取命中节奏；而在 `1600×960`（`original960` 与 `small900`）的小工作集下，`submit_pulse=1` 或更小的特征图完全驻留于缓存中，因此 `original960`（`-27.99 µs`）和 `small900`（`-12.71 µs`）3/3 轮全胜。

## 2. 分支 K4：`sp_run256_w16` 开启 `W2_QKV_FUSE` 与 `W2_HOIST_LOADS=3`

### 2.1 COMGR（gfx1201）ISA 与 Spill 演进审计
在 `hip/wave_owned_mh.inc:566-589` 中，首先发现一处宏掩码陷阱：`W2QkvFuse` 的启用条件为 `(C==256 && (W2_QKV_FUSE & 4))`，而 `W2QkvPair`（Q+K 成对共享 `plane0` 读取、V 单独第二轮读取）为 `C==256 && (W2_QKV_FUSE & 8)`。若仅定义 `W2_QKV_FUSE=8` 而不置 bit 2（`4`），`W2QkvFuse` 为 `false`，代码根本不会进入融合分支！
さらに，当开启 `W2_QKV_FUSE=12`（`4|8`）或 `4` 时，默认内层 `for(uint kt=0; kt<16; kt++)` 完全展开会使 `sp_run256_w16` 触顶 256 VGPR 并产生 `11~17` 寄存器 spill（`48~72B` scratch）。通过开启 bit 4（`16`，即 `W2_QKV_FUSE=28 = 4|8|16` 禁用内层 `kt` 展开）并在 `sp_recover_body` 中保持非融合以保护其 43 SGPR/局部循环变量压力（变体 `k4j`），实现了 **`sp_run256_w16` 与 `sp_recover256_w16` 双核 0 spill、0 private**：

| 变体 | 配置 | `sp_run256_w16` VGPR | `sp_run256_w16` Spill / Priv | `sp_run256_w16` 指令数 | `global_load` | `ds_load` | `sp_recover256_w16` VGPR (Spill) |
|---|---|---:|---:|---:|---:|---:|---:|
| **Baseline** | `W2_QKV_FUSE=0, W2_HOIST_LOADS=0` | **184** | **0 / 0** | 5,246 | 503 | 129 | 235 (0) |
| `k4a` | `W2_QKV_FUSE=12, W2_HOIST_LOADS=3` (`kt` 展开) | 256 | 11 / 48B | 4,834 | 503 | 65 | 240 (0) |
| `k4b` | `W2_QKV_FUSE=4, W2_HOIST_LOADS=3` (`kt` 展开) | 256 | 17 / 72B | 4,825 | 503 | 65 | 240 (0) |
| **`k4c`** | **`W2_QKV_FUSE=0, W2_HOIST_LOADS=3`** | **184** | **0 / 0** | **5,150 (`-96`)** | 503 | 129 | 240 (0) |
| **`k4`** (`k4j`) | **`W2_QKV_FUSE=28, W2_HOIST_LOADS=3`** (`kt` 循环) | **253** | **0 / 0** | **3,923 (`-1323`)** | **143** | **41** | **240 (0)** |

## 3. 分支 K5：`c64/c128_wave2_up_lb_sh` 折叠首 barrier 前 `qt` 循环 + `c64_wave2` 全系压入 `<=191` VGPR（8 waves/SIMD）

### 3.1 LLVM 23 寄存器活跃度根因剖析与双优化实装
1. **首 barrier 前 `qt=0..3` 循环折叠（`wave_owned_mh.inc:352`）**：
   - 将 `W2_UP_VEC` 分支的 `_Pragma("unroll") for(uint qt=0; qt<4; qt++)` 改为 `_Pragma("clang loop unroll(disable)") for(uint qt=0; qt<4; qt++)`，消除了首 barrier 前 4 倍重复的 Up 采样、残差混合与 `ds_bpermute` 展开代码：
     - `c64_wave2_up_lb_sh` 静态指令数从 **`4,526 -> 3,471`（净砍 `-1,055` 条指令，`-23.3%`）**！
     - `c128_wave2_up_lb_sh` 静态指令数从 **`4,586 -> 3,609`（净砍 `-977` 条指令，`-21.3%`）**！
2. **定位并斩断 `c64_wave2` 跨 192 VGPR 悬崖的罪魁祸首（`199 -> 191` VGPR）**：
   - 为什么 `c64_wave2_bi_bo`（199 VGPR）和 `c64_wave2_bi_ho`（199 VGPR）差 7 个 VGPR 进不了 192 桶（8 waves/SIMD，4 WGs/CU）？
   - 通过逐行解剖 LLVM 23 生成的 `c64-wave2-fast.hsaco.s` 发现：在 FFN `for(uint ht=0; ht<8; ht+=T)` 循环开始前（第 259-270 行，首个 `s_barrier` 信号与等待之间），LLVM 23 的 LICM（循环不变量外提）将 `w2_weight(fw+4*C*C, head*32+ci*16+rc, 4*C, head*128+(ht+tile)*16)` 的 **4 个 64 位基地址指针**（`v[100:101], v[102], v[103:104], v[105:106]`，共 **7 个 VGPR**）外提到了 `qb` 和 `ht` 双重循环之外！这 7 个 VGPR 在整个 FFN Expand + GELU 激活期间全程保活，恰好把峰值寄存器从 `191` 顶到了 `199`！
   - 仅对 `C==64` 在 `ht` 循环头部重取一次线程坐标（`if constexpr(C==64){uint ffn_tid=__builtin_amdgcn_workitem_id_x(); __asm__ volatile("":"+v"(ffn_tid)); ...}`），在不改变 `B=4, T=2` 批处理因子、不增加任何 `ds_load`/`global_load`、不改变 `C128/C256` 任何一条指令的前提下，**将 `c64_wave2` 全系 8 个核全部压入 `189 ~ 191` VGPR（`<= 192` 桶，8 waves/SIMD = 4 WGs/CU，0 spill，且静态指令数再减 33 条）**：
