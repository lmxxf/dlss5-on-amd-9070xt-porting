# GPU adaptive ViT reuse (AttExp only)

This experimental host/module ABI is a matched pair. Do not install the guarded module with an ordinary release DLL. Generated sources live under /tmp/vit-adaptive-src; production sources remain unchanged.

Pipeline: one wave per token measures input delta against the last exact anchor, excluding padded spatial tokens using the Gather permutation; one wave combines global relative L1 and worst-token relative L1; each ViT entry exits early when reuse is allowed; a finish kernel selects gain prediction or exact output and updates anchors only for exact frames. All operations run on the same HIP stream. No CPU decision readback unless diagnostic logging is explicitly enabled. Readback is excluded from timing.

Global relative L1 uses sum(abs(delta))/sum(abs(anchor)); token ratio denominator has floor16 (mean1/64) to avoid exploding ratios on near-zero tokens. Provisional thresholds0.20 global/1.0 worst-token are heuristics, not error bounds. Maximum period4; initial state and processing gaps>500ms force refresh. Modes: DLSS5_VIT_ADAPTIVE=0 full baseline;1 adaptive;2 force full through the wrapper;3 forced GPU schedule. Mode0 must be used with REUSE_PERIOD=0 in the initial r1 runner. Requires Graph off, fast pooled pipeline, byte-stream ViT off, no skipped blocks31–38 (existing decoder skip42/43/46 allowed).

Build: build-host.sh; upload generated kernel as hip-backend/vit-residual-adaptive.hip; residual/build.ps1 -Suffix -adaptive assembles isolated modules. run.ps1 Control verifies static900/1080 baseline/disabled/forcefull/fixed/adaptive. suite.ps1 Quality evaluates sequences1–7 at900; Timing runs160-frame ABBA on static/shift/combined-motion900/1080. Exclude32 warmup frames and use means. Diagnostic collection/transfer must finish before timing.

Sequences1–4 follow previous residual experiments;5 vertical2px/frame plus exposure modulation,6 a1%-area black patch appearing/disappearing,7 repeated mirrored cuts. Sequence steps repeat every12 frames for dynamic timing; input preparation occurs before the measured ProcessSubmittedFrame interval. These are controlled derivatives of one captured HDR image, not real game motion. Quality compare uses exact per-frame references and confirms every recomputed frame matches bitwise. First-frame cold weight upload may cause a subsequent500ms timeout and restart GPU epoch counts; frame position in the capture remains authoritative.
